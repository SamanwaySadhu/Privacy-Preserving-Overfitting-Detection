# Directional-sharpness certification: baseline + adaptive attack

Scenario: **certification** (paper Sec. 3.1/5.3). The verifier never sees the training set D. The prover holds
(w0, D), runs the public audit (Algorithm 1) with a public seed and proves `F(w0, D, r) <= tau`. The verifier only
learns that predicate. Threshold `tau` is calibrated on models of known quality (95th percentile of `F` over benign
calibration models, i.e. <=5% false rejections). The attack is the technical note's Eq. (5).

Everything runs on CPU. Full numbers: [results/RESULTS.md](results/RESULTS.md) (generated by `summarize.py` from `results/*.json`).

## Files
| file | purpose |
|---|---|
| `common.py` | models (LeNet5, SimpleCNN, 2FC, ResNet18), data, training, **differentiable re-implementation of the audit** (B=16, T=10, lr=1e-4, rho=0.05, ASAM sharpness) |
| `baseline.py` | trains benign/faulty models, calibrates `tau`, reports TPR/FPR on held-out models (`--reuse` re-audits saved models) |
| `attack.py` | adaptive attack: unrolls the audit, 2nd-order backprop, Eq. (5) objective, evaluates on fresh seeds with the original `tau` |
| `diagnose_variants.py` | which score variants separate benign/faulty |
| `sanity_lookup.py` | checks the audit against the note's exact SAM lookup-model counterexample |
| `summarize.py` | builds `results/RESULTS.md` |

Run: `python baseline.py --task {2fc,simplecnn,lenet5,resnet18} --k-cal 3 --k-eval 3 --n-seeds 30`, then
`python attack.py --task simplecnn --stat ratio --models faulty_eval0 --iters 800 --lr 1e-3`.

## Setup
| task | data (D = train subset) | model | faulty model |
|---|---|---|---|
| resnet18 | CIFAR-10, 4000 | repo's `Cifar10NarrowResNet(k=1)` (3x3 blocks, widths 16/32/64, 0.27M params) | 20% label noise |
| lenet5 | CIFAR-10, 4000 | repo's LeNet5 | 20% label noise |
| simplecnn | FashionMNIST, 4000 | repo's SimpleCNN (1 conv + fc) | 20% label noise |
| 2fc | German credit, 640 (160 more rows = attacker's Q) | repo's TabularNet (128, 64) | 20% label noise |

Benign = clean labels; faulty = memorizes 20% wrong labels (paper's "noisy labels" deviation). Both stopped at 90% train accuracy
(SGD, momentum .9, wd 5e-4). The audit runs on the **authentic clean D** (D is authenticated in the threat model), so the faulty
model's loss on D is high. 2-3 calibration + 2-3 evaluation models per class, 20-30 public audit seeds per model.

Two fluctuation statistics are certified because the paper text and artifact disagree:
`log` = Std_t log(s_t^2/L_t + eps) (paper Sec. 4.2 text) and `ratio` = Std_t s_t^2/L_t (artifact `FLAT2_OVER_LOSS_STD`; the artifact has no log variant).

## Baseline results (held-out models; verifier never sees D)
| task | stat | benign test acc | faulty test acc | AUC | benign accepted | **faulty rejected** |
|---|---|---|---|---|---|---|
| simplecnn | ratio | 0.851 | 0.747 | 1.00 | 0.96 | **1.00** |
| simplecnn | log | | | 0.22 | 0.92 | 0.00 |
| 2fc | ratio | 0.748 | 0.660 | 0.87 | 0.99 | **0.51** |
| 2fc | log | | | 0.40 | 0.96 | 0.00 |
| lenet5 | ratio / log | 0.422 | 0.312 | 0.19 / 0.09 | 0.90 / 0.87 | 0.02 / 0.00 |
| resnet18 | ratio / log | 0.544 | 0.403 | 0.38 / 0.14 | 0.90 / 0.93 | 0.03 / 0.00 |

(AUC = P[faulty F > benign F]; 0.5 = no separation, <0.5 = inverted.)

* The statistic **as written in the paper (log-ratio std) does not separate** benign from memorizing models in any of my four settings
  (AUC 0.1-0.4, i.e. the faulty models are, if anything, *less* variable). The artifact's `Std(s^2/L)` does for SimpleCNN and 2FC.
* On both CIFAR-10 tasks the "benign" model itself badly overfits (loss gap 1.7-2.8) because D has only 4000 samples, so there is
  no good reference class and neither statistic detects anything. These two baselines are negative results.

## Attack results (Eq. 5, evaluated on 50 fresh seeds with the original tau; held-out faulty models)
| task | stat | pass before | pass after | test acc before -> after (benign ref) | notes |
|---|---|---|---|---|---|
| simplecnn | ratio | 0/50, 0/50 | **50/50, 50/50** (800 it; 70%/62% at 200 it) | 0.750->0.734, 0.744->0.741 (0.851) | overfitting fully kept |
| 2fc | ratio | 8, 21, 41 /50 | **50/50 x3** | 0.665->0.700, 0.655->0.720, 0.660->0.700 (0.748) | repairs part of the gap: "damage retained" 0.32-0.55 (beta=1), 0.55-0.89 (beta=10) |
| simplecnn / 2fc / lenet5 | log | already ~96-100% | 100% | unchanged within ~1pp (one 2fc model +6pp) | nothing to break: baseline already accepts these models |
| lenet5 | ratio | 48/50, 50/50 | 50/50 | unchanged | already accepted |
| resnet18 | ratio | 20/20 | 20/20 | 0.427->0.425 | only a 20-iteration cost probe (~20 s/it on CPU, 1 seed per iteration); uninformative since already accepted |

So where the certificate actually detects overfitting (SimpleCNN, 2FC with the `ratio` statistic), the adaptive attack gets the memorizing
model accepted at 100% of fresh seeds while keeping its train fit (~0.89-0.92 on the memorized labels) and, for SimpleCNN, its
poor test accuracy. For 2FC the attack partially "repairs" generalization as a side effect (anchor beta=10 helps).

## Sanity check of the note's analytic claim (`sanity_lookup.py`)
Lookup model + squared loss + SAM sharpness: `s^2/L = 2 rho^2/B` at every step, F = 1e-6 (fp noise). With ASAM sharpness and unequal weights F = 0.03-0.10,
so the note is right that the SAM argument does not carry over to ASAM unchanged; the numerical attack above is what works against ASAM.

## Caveats
* Scaled-down CPU study: small D, tiny "ResNet18" (the repo's narrow variant), 2-3 models per class, one attack seed. Not a replication of the paper's VGG/CIFAR-scale numbers; AUCs/TPRs here should not be read as contradicting them.
* BatchNorm is frozen (eval mode) in the audit, so it is differentiable and ZK-friendly; the artifact uses train-mode BN in the SAM update.
* `eps=1e-10` for the log statistic and the exact batch-sampling scheme (public permutation, consecutive blocks) are my choices.
* "Damage retained" is a heuristic summary; the success criterion in the note (low train loss + large held-out gap + high pass rate) is met for SimpleCNN, only partially for 2FC.
* The attacker's Q is real unlabeled data from the same distribution (disjoint from D and the test set); results with weaker Q are not tested.
* The attack is white-box on the public audit and not a cryptographic break; ZK proving of the predicate was not implemented (only the metric is evaluated).
